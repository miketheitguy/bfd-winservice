# BFD Windows Service 5.0.0

## Version and compatibility

Version 5.0.0 is a major release under the repository's version policy.
Authenticated Windows service configurations require a machine-scope
DPAPI-protected `REG_BINARY` value at `Parameters\Secrets\AuthKeyDpapi`.
This changes the supported persisted configuration contract from version 4.0.0.
Packet authentication formats, key IDs, and mode-specific key lengths are
unchanged. Programmatic Rust authentication inputs remain available.

## Functionality and security

- Store BFD authentication keys as DPAPI ciphertext without optional entropy.
  The protected Secrets ACL grants SYSTEM and Administrators full control and
  the BFD service SID read access. The restricted LocalService service reads
  and decrypts the key before starting the packet engine.
- Install `Set-BfdAuthenticationKey.ps1` for elevated, stopped-service key
  administration. It accepts hidden ASCII or hexadecimal input, checks the
  protected ACLs and key length, and verifies persisted ciphertext by
  decrypting it. Failed verification restores the preceding encrypted value;
  unrelated registry values are left untouched.
- Bound encrypted registry reads and reject missing, malformed, inaccessible,
  or invalid authentication material. Clear owned plaintext buffers on release
  and keep key contents out of diagnostics.
- Preserve the encrypted key during installer repair and reapply its protected
  ACL independently. Add provisioning, DPAPI, and installed-token regression
  coverage.
- Refresh operator and developer documentation, remove obsolete deployment
  material, and provide current review and validation checklists.

## Validation

Release preparation passed:

- All 296 optimized Rust tests, including three doctests.
- All 29 focused ASan configuration tests, with native instrumentation verified.
- Both opt-in native RPC/MI coexistence tests.
- Strict release Clippy, API documentation, and formatting checks.
- Release version, ACL, DPAPI provisioning, rollback privilege, installer
  hardening, and native runtime policy fixtures.
- Both production executable hardening checks and the version 5.0.0 offline
  setup bundle's MSI tables, payload, and runtime prerequisite checks.
- Documentation link, heading, sample-syntax, and source-coverage checks.

CI independently runs its ASan, fuzz, and disposable installation gates before
publishing release assets.

Installed-service DPAPI tests performed during implementation verified the real
LocalService restricted token, protected Secrets ACL, rejection of missing or
corrupt ciphertext, and key preservation during repair. Those tests precede
version stamping; they are not a fresh installation test of the 5.0.0 bundle.
Native fixtures do not establish external peer interoperability or timing under
production load.
