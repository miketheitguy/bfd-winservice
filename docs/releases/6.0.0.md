# BFD Windows Service 6.0.0

This record helps Windows administrators and Rust library users review the
combined scheduling and secret-storage changes and their validation evidence.

## Version and compatibility

Version 6.0.0 is a major release under the
[version selection policy](../../CONTRIBUTING.md#choose-a-release-version).
The public Rust fields `Options.auth_key` and `Options.auth_key_hex` now accept
`Option<secrecy::SecretString>` instead of `Option<String>`. Callers that assign
an owned `String` must convert it with `.into()`, for example:

```rust
use bfd_winservice::config::Options;
use bfd_winservice::packet::AuthType;

let local = "192.0.2.1".parse().unwrap();
let peer = "192.0.2.2".parse().unwrap();
let mut options = Options::new(local, peer);
options.auth = AuthType::MeticulousSha1;
options.auth_key = Some(String::from("example-only").into());
```

`AuthConfig::new` continues to accept `Vec<u8>`. The installed registry layout,
DPAPI ciphertext format, authentication modes, key IDs, BFD packet formats,
and private RPC contracts remain compatible with 5.0.0. Existing protected keys
do not require reprovisioning. Authentication and key changes require a service
restart. With authentication disabled, startup ignores stored secret material.

## Scheduling changes

The BGP broker uses event-driven request dispatch, and the packet engine
coalesces routine telemetry wakes. BFD transmit intervals, detection timeouts,
and BGP state-driven actions remain unchanged. See
[runtime behavior](../service-communication.md#runtime-behavior) for the scheduling
contract. Measurements are maintained separately in [Performance](../performance.md).

## Secret ownership

Authentication configuration clones share immutable `SecretSlice` storage through
`Arc`. The final owner zeroizes it on drop. Validation releases the original
secret input fields, avoiding retained duplicate plaintext. DPAPI decryption
occurs once during authenticated startup; live S-BFD settings updates retain
that key without reading or decrypting it again.

Native DPAPI buffers, temporary key buffers, and runtime transmit buffers use
zeroizing owners. `AuthConfig::new` wipes its supplied vector on success and
failure. Key-byte equality uses a constant-time comparison. See
[library development](../development/library.md#raw-options-encoding-and-registry-loading)
for ownership limits and caller responsibilities, including Simple Password
output returned by `ControlPacket::encode`.

The VM installer tests used a checkpoint of the dedicated `BFD-WS2025` guest.
Its retained lab logs were preserved before the clean-install fixture. The
checkpoint was restored before upgrading the original lab installation to
6.0.0. The first host ASan run collided with a concurrent test suite's UDP bind;
the full rerun after the other socket tests finished passed without sanitizer
findings.

The RRAS restart matrix initially stopped on a sampler race between SCM Running
and provider readiness. The lab harness now treats only the `0x800710dd`
service-not-running query result as unavailable within its existing bounded
readiness loop; other query failures remain errors.

The [machine-readable validation record](../validation/6.0.0.json) includes build
input and artifact hashes, native test counts, lab harness identities, scenario
outcomes, and restoration results. Detailed local logs remain under
`target/release-6.0.0` and `target/bird-interop/release-6.0.0`.

Three doctests ran on the Windows build host; the VM executed prebuilt native
test harnesses. Miri was not run because its component is not installed for the
pinned toolchain on this host. ASan does not instrument Windows system DLLs or
the prebuilt MSVC runtime. This two-vCPU, one-peer lab does not establish
production capacity, worst-case scheduling latency, or long-term leak freedom.
