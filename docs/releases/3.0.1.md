# BFD Windows Service v3.0.1

Cowabunga, release crew. BFD's BGP control failures now reach Event Viewer
when file logging is disabled, and native UDP tests tolerate occupied source
ports on shared build runners.

## Compatibility and version selection

The published baseline is v3.0.0. This change set contains compatible bug fixes,
so **v3.0.1** follows the
[version policy](../../CONTRIBUTING.md#choose-a-release-version).
Existing Rust APIs, command-line options, registry settings, authentication,
BFD wire behavior, service identities, and private RPC interfaces are unchanged.
No configuration migration is required.

Upgrade both services together with `BfdWinService-3.0.1-x64-setup.exe`.
Distribution remains the offline setup executable and its SHA-256 checksum,
with the same supported Windows versions and runtime requirements.

## Fixed

- Publish BFD-side BGP control RPC failures and recovery to the Operational
  event channel even with `LogToFile=0`. New events 302 and 303 identify the
  peer and requested operation; existing events retain their meanings.
  Repeated failures are limited to one event per minute, and recovery requires
  a successful functional RPC call. A superseded local action cannot report
  recovery. See [BGP control telemetry](../logging.md#bgp-control-broker-and-rpc-telemetry-events)
  for the event fields and interpretation.
- Allocate available source ports for native UDP fixtures instead of assuming
  particular high ports are free. Explicit source-port configuration remains
  covered. Production port allocation and protocol destination ports are
  unchanged.

## Validation

The [merged fix and passing pull-request checks](https://github.com/miketheitguy/bfd-winservice/pull/2)
cover optimized tests, Rust/native AddressSanitizer, bounded fuzz campaigns,
executable hardening, and native installer, bundle, and upgrade validation.
All 13 native UDP tests also passed while the eight former fixed source ports
were held by exclusive sockets.

A Windows VM running the fix was tested against BIRD with file logging disabled.
The checks verified rendered failure events, repeat suppression over a minute,
one recovery event after broker restoration, BGP stop and route withdrawal,
and subsequent BFD/BGP route recovery. This diagnostic test supplements the
v3.0.0 interoperability run; it does not repeat that run's full authentication
and interruption matrix.

Publication requires the full release-tag workflow to pass again for the
versioned source. See the [validation guide](../development/validation.md)
for the checks and their limits.
