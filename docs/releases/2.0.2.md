# BFD Windows Service v2.0.2

This patch release restores automatic Windows RRAS BGP recovery after BFD
failure and corrects the corresponding broker event messages.

## Fixes

- Read BGP connectivity status using the Windows RemoteAccess module's enum
  contract. RRAS status queries work when CIM enum qualifiers are absent;
  unknown values remain errors rather than authorizing a Start.
- Handle successful RRAS Start/Stop calls that return empty method output.
  Require successful MI completion and read the selected peer back before
  reporting success. Invalid or nonzero explicit return values remain errors.
- Add native regression fixtures and an opt-in read-only RRAS status test.
  Document the provider behavior and the live withdrawal/recovery evidence.

## Validation

On Windows Server 2025 with Ubuntu 26.04.1 and BIRD 2.18, the fixed broker
passed a two-minute stable baseline and three BFD failure/recovery cycles.
Windows stopped the BGP peer, removed BIRD's /32 from its BGP and active route
tables, then restarted the peer and restored the route after BFD recovered.
Events 103/201, 102, and successful Stop/Start event 300 messages matched the
transitions without broker errors during the cycles. BGP-only route withdrawal
and protocol restart also recovered while BFD stayed Up. See the
[dated lab report](../windows-bgp-interop-2026-10-22.md) for timing, isolation,
and coverage limits.

## Compatibility and version selection

The published baseline is v2.0.1. These changes fix existing service behavior
without adding a product feature or changing the supported CLI, registry
schema, Rust public API, RPC wire layout, service identities, Windows support,
or installer contract. The complete change set therefore warrants the patch
increment to v2.0.2 under the repository's release policy.

Upgrade with `BfdWinService-2.0.2-x64-setup.exe`. Existing configuration and logs
are retained; no configuration migration is required. Distribution remains the
offline setup executable and its SHA-256 checksum.
