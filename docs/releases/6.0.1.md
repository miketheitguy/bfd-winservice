# BFD Windows Service 6.0.1

This release helps maintainers run installation tests without delayed Windows
recovery actions interfering with later service-stop checks.

## Version and compatibility

Version 6.0.1 is a patch release under the
[version selection policy](../../CONTRIBUTING.md#choose-a-release-version).
The change fixes test isolation and adds failure diagnostics. Public Rust APIs,
registry settings, authentication storage, BFD/BGP behavior, and installed
service recovery policy remain compatible with 6.0.0. No migration is required.

## Fixed

The privilege-policy and missing/corrupt-key tests intentionally reject service
startup. With non-crash recovery enabled, those failures schedule Windows
Service Control Manager (SCM) restarts. A subsequent manual start and stop do
not cancel a queued restart. The restart can occur during `Stop-Service` and
cause a timing-dependent `StopServiceFailed` error.

The tests suppress non-crash recovery only around those expected startup
failures. A `finally` block restores and verifies the original flag before
normal startup and shutdown tests. Crash recovery actions retain their installed
configuration, and the broker crash-recovery test still runs.

Installation-test failures also capture service states, process IDs, exit codes,
SCM events, and selected service lifecycle/RPC events before uninstall cleanup.
CI uploads this bounded diagnostic file with the installer logs. The capture
excludes registry settings, authentication material, and process command lines.

## Investigation evidence

The 6.0.0 VM investigation reproduced the exact PowerShell error in two of four
cases near a queued restart boundary. In one case, SCM recorded `Stopped`, then
`Running` about 66 milliseconds later with a different process ID. Suppressing
non-crash recovery during the rejected starts, then restoring it before the
healthy start, passed all four comparison cases.

These are targeted timing cases, not estimates of a production failure rate.
The original failed CI runner did not capture its service-state timeline; the
matching VM reproduction supports the diagnosis. See Microsoft's
[queued restart behavior](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-changeserviceconfig2w).
